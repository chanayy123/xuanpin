# 内部选品决策站

用于从淘金出海当前供应目录中挑选**相对值得先打样、核价和测款的品类**。默认结合现有布艺 POD 工作流、同 SKU 供货成本、重量、标称发货时间和运营复杂度；抱枕套保留为现有业务对照。市场销量和利润未经验证时不参与排名。

## 打开站点

Windows 双击根目录的 `启动最新版选品站.bat`。它从 `feature/catalog-sync-dashboard` 的 GitHub Actions 构建产物读取最新站点，在 `http://127.0.0.1:4173/` 本地打开。站点只监听本机；运营清单保存在当前浏览器，可导出备份与交换，不是多人实时数据库。

开发运行：

```powershell
npm ci
npm run dev
```

## 使用顺序

1. 查看品类榜，按默认 POD、小预算或物流优先策略比较候选。
2. 打开品类查看得分依据、资料覆盖、风险、推荐商品和同 SKU 参数。
3. 对比前三类，并把代表商品加入测款清单。
4. 在情景测算中填入真实卖家结算收入和费用。Temu 买家端美元零售价不能替代卖家核价。
5. 打样、核价、上架和收集测款结果，记录清单状态及备注；导出 JSON 留存。
6. 从“数据与方法”检查来源日期、同步是否失败，以及哪些市场证据尚未补齐。

## 数据与排名

- `public/data/catalog.json`：完整分页的供应商品与 SKU 数据。
- `public/data/category-rankings.json`：全部品类、三种权重方案、分项解释和推荐样品。
- `data/category-playbooks.json`：可编辑的工作流与运营复杂度判断，明确标注为内部判断。
- `public/data/market-evidence.json`：既有市场证据、日期、范围和限制。
- `public/data/daily-sync.json`：最近流水线结果、计划时间、实际运行链接与失败阶段。
- `data/source/latest/`：最近一次成功同步的公开源响应及哈希清单。
- `research/cosmetic-bag/2026-09-23/`：化妆包原始研究与销量口径调查。

排名只比较本站实际覆盖的供应候选，并非全 Temu 市场榜。来源中存在类目误归时按明确商品用途重新分组，仍保留原始类目映射。多件套的供货价按来源 SKU 的销售单位显示，不能擅自除成单件价。体积重使用统一系数估算，实际运费需承运商报价。

THunt 两个关键词的共同商品出现销量冲突，Temu 登录会话曾受风控。所有真实库存结论保持未知。2026-09-28 的跨品类 Google Trends 页面返回 429，未获得数据；不会把失败当作低需求，也不会把旧样本日期更新成今天。

## 每天同步

计划每天北京时间 **08:15**，GitHub 的实际调度可能延迟。默认分支上的调度配置触发应用分支，执行：

```text
供应目录全量采集 → 公开原始证据 → 粗筛 → 市场证据索引 → 品类重排 → 测试 → 构建 → 发布内部构建产物
```

任何采集或校验失败会保留最近成功的数据，并在站点展示失败状态和最后成功时间。市场页面的人工验证与供应目录的自动更新分别记录；每日同步不会绕过 Temu 风控，也不会自动编造市场销量。

本机也可以完整运行 `npm run daily`。只重算品类可运行 `npm run rank`，只生成市场来源索引可运行 `node scripts/build_market_evidence.js`。

调度配置模板：`scripts/config/daily-catalog-scheduler.yml`。默认分支只保存调度入口，应用位于功能分支；部署方式和自动更新细节见 [WINDOWS_LAUNCHER.md](WINDOWS_LAUNCHER.md)。

## 验证

2026-09-28 已通过 35 项 `npm test`、完整 `npm run daily` 流水线和生产构建。浏览器验收通过排名策略切换、搜索与筛选、候选对比、测款清单状态及备注持久化、JSON 导入导出、CSV 导出、测算必填及负数校验、来源日期、同步失败保留快照、数据版本不一致保护，以及 390px 窄屏排名和对比页面布局。

这些检查验证了程序和资料链路；未验证真实卖家核价、承运商收费、需求规模或实际经营利润。外部商品图片加载失败时显示占位提示，不影响供货参数与来源查看。
